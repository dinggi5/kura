[새로 생긴 것]

• 세 번째 네트워크 「Arc 테스트넷」 — Circle이 만든 체인이에요. 설정 → 네트워크에서 고를 수 있어요. 이 체인은 가스도 USDC로 내서 「가스용 ETH가 따로 필요한」 문제가 없어요. 그래서 ETH 잔액 줄과 ETH 보내기가 없고, 송금할 때는 가스 몫으로 0.01 USDC를 남겨 둬요. 아직 x402 결제를 받아 정산해 주는 곳이 없어서, 지금은 잔액·송금까지예요.

• AI가 결제 요청에 상대의 에이전트 번호(ERC-8004)를 붙일 수 있어요 (CLI는 kura pay --agent 번호). 받는 주소가 온체인에 등록된 지갑과 다르면 승인 창에 경고하고, 자율 결제로는 나가지 않아요.

• 지갑 창이 멈췄을 때(앱은 살아 있는데 화면이 응답하지 않을 때) AI의 결제 요청을 5분 동안 기다리게 두지 않고 그 자리에서 알려요. OS 알림도 띄워요. 창을 다시 띄우면 저절로 돌아와요.

• 계정을 여러 개 둘 수 있어요 — 화면 맨 위의 계정 이름을 누르면 계정을 바꾸거나 새로 만들 수 있어요(메타마스크와 같은 방식). 시드는 하나라 백업은 지금 그대로예요 — 12단어만 있으면 모든 계정이 같은 주소로 다시 나와요. 다만 복구 직후엔 계정이 하나만 보여요. 전에 더 쓰셨다면 다 나올 때까지 「새 계정」을 눌러 주세요 — 같은 순서로 같은 주소가 돌아와요. 계정에 붙이신 이름은 복구되지 않아요. 잔액·받기·보내기·거래 내역은 지금 고른 계정 기준이고, AI도 그 계정으로 결제를 요청해요. 한도와 신뢰 주소는 지갑 전체에 하나예요(계정을 늘려도 하루 한도가 늘지 않아요). 승인 대기 중엔 계정을 못 바꾸고, 요청이 만들어진 계정과 다른 계정에서는 승인되지 않아요.

• 결제 승인 창을 잠시 닫을 수 있어요 — 승인 전에 다른 걸 확인해야 할 때 메뉴바 아이콘을 누르면(또는 ⌘W) 창이 내려가요. 요청은 그대로 기다리고, 아이콘을 다시 누르면 그 자리에서 이어져요. 닫아 둔 채 잊으면 만료 1분 전에 한 번 다시 떠요. 전에는 승인 창이 떠 있는 동안엔 아이콘을 눌러도 닫히지 않았어요.

[고친 것]

• AI 결제가 드물게 두 번 나갈 수 있던 틈 세 가지를 막았어요 — 승인 도중 화면이 멈췄을 때, 승인 도중 네트워크를 바꿨을 때, 잔액 조회가 오래 걸려 요청이 만료된 뒤 나가려 할 때.

• x402 결제에서 서버가 다른 서명 방식(extra)을 요구하면 이제 서명하지 않고 이유를 알려요. 전에는 비밀번호까지 넣은 뒤에 서버가 조용히 거절했어요.

• 승인 창의 「요청한 곳」 주소가 서버가 주장한 문자열이 아니라 실제로 접속한 주소예요. 대조하지 않은 도메인은 승인 창에 띄우지 않아요 (등록은 누구나 할 수 있어서, 대조 없이 이름만 띄우면 사칭에 쓰일 수 있어요).

• 잔액 전부를 보내려 할 때 가스 몫이 모자라는 걸 승인 창과 자율 결제에서 미리 잡아요 (Arc처럼 가스를 USDC로 내는 체인).

• 설정 파일(~/.jigap/settings.json)을 읽지 못해 기본값으로 돌 때 지갑 화면에 알려요. 그 상태에서는 고르신 RPC 대신 공식 RPC가 쓰이는데, 전에는 그 사실을 알 길이 없었어요.

• AI에게 「지갑 앱이 실행 중이 아니에요」 한 가지로만 답하던 걸, 지갑이 없을 때 · 비밀번호를 아직 안 정했을 때 · 앱이 꺼졌을 때 · 화면이 멈췄을 때로 나눠 정확히 말해요.

• CLI가 요청을 검사하기도 전에 「승인을 기다리는 중…」을 찍던 순서를 고쳤어요. 「테스트넷를」 같은 조사 오류도 고쳤어요.

[What's new]

• A third network, 「Arc testnet」 — a chain built by Circle. Pick it in Settings → Network. Gas there is paid in USDC, so there is no separate 「you also need ETH for gas」 problem: there is no ETH balance line and no ETH send, and when you send, 0.01 USDC is kept back for gas. Nobody settles x402 payments on Arc yet, so for now it is balances and transfers only.

• The AI can attach the other side's agent number (ERC-8004) to a payment request (CLI: kura pay --agent N). If the receiving address differs from the wallet registered on-chain, the approval window warns you, and it never goes out under autopay.

• When the wallet window hangs (the app is alive but the screen stops responding), the AI's payment request is answered right away instead of waiting five minutes, and an OS notification is shown. Bringing the window back recovers on its own.

• The wallet can hold several accounts — tap the account name at the top of the window to switch or add one (the same way MetaMask does it). There is still one seed, so your backup does not change: the 12 words bring every account back at the same addresses. Right after a restore, though, you will see only one account — if you had more, tap "New account" until they are all back, and they return in the same order at the same addresses. The names you gave them are not restored. Balance, receive, send, and history follow the account you picked, and the AI pays from that account too. Limits and trusted addresses stay wallet-wide (adding accounts does not raise the daily cap). You can't switch accounts while an approval is waiting, and a request made for one account is never approved from another.

• You can put the approval window away for a moment — click the menu bar icon (or ⌘W) when you need to check something before approving. The request keeps waiting, and clicking the icon again picks up right where you were. If you forget about it, the window comes back once, one minute before the request expires. Before, the icon did nothing while an approval was showing.

[Fixed]

• Closed three gaps where an AI payment could rarely go out twice — when the screen hung mid-approval, when the network was switched mid-approval, and when a slow balance lookup let an already-expired request go out.

• In x402, when a server asks for a different signing scheme (extra), Kura now declines and says why instead of signing. Before, the server would quietly reject after you had already typed your password.

• The 「requested by」 address in the approval window is now the address actually reached, not the string the server claimed. Domains that were not actually checked are no longer shown there (anyone can register, so an unchecked name is an impersonation vector).

• Sending your whole balance on a chain that pays gas in USDC (Arc) is caught before approval — in the approval window and in autopay — instead of failing on-chain.

• When the settings file (~/.jigap/settings.json) can't be read and Kura falls back to defaults, the wallet screen now says so. In that state the official RPC is used instead of the one you chose, and before there was no way to know.

• Instead of one 「The wallet app isn't running」 answer to the AI, Kura now distinguishes: no wallet yet · no password set yet · app not running · screen not responding.

• The CLI printed 「Waiting for approval…」 before it had even checked the request; fixed the order. Also fixed a Korean particle error (「테스트넷를」).
